# Интеграция BSLexicon с книгами

BSLexicon работает как «языковой backend» для книг по 1С. Две части
интеграции — разные по природе, поэтому лежат отдельно:

| Что | Куда | Документ |
|---|---|---|
| Sandbox-листинг (код из главы, «попробовать в редакторе») | Живёт **в главе** как ` ```bsl,песочница `. Ссылку собирает книга через URL-контракт. | [`url-contract.md`](./url-contract.md) |
| Задача Judge (условие + чек-поинты) | Живёт **в `tasks/`** как YAML. Книга публикует `tasks.json` релиз-ассетом. | [`task-schema.md`](./task-schema.md) · [`task-schema.json`](./task-schema.json) |
| QR-коды на бумаге | Отдельная тема — генерируется в pipeline книги. | [`qr-guide.md`](./qr-guide.md) |

## Главное правило

**Один листинг — один источник.** Если код есть в главе как sandbox —
его нет в `tasks/`, и наоборот. Дублирование гарантированно разъедет
две версии.

Sandbox — про «прочитал → потрогал». Judge — про «попробовал → проверил
на скрытых кейсах → перешёл дальше». Разная функция, разное место.

## Список поддерживаемых книг

BSLexicon реализует **язык**, не платформу — у нас нет форм, регистров,
метаданных. Поэтому задачи имеют смысл только из книг серии, работающих
с языком:

| Книга | book_id | Registry |
|---|---|---|
| «1С как иностранный язык» | `1c-reading-code` | [catalog/books.yaml](../../catalog/books.yaml) *(добавится в след. пуше)* |
| «1С-разговорник» | `1c-razgovornik` | так же |

Книги про метаданные (`reading-metadata`), формы (`reading-forms`) и
регистры пойдут в другой инструмент.

## Как это будет ощущаться читателем

1. Читатель открывает главу в mdBook, видит sandbox-листинг → кликает
   «Запустить» → тренажёр открывается в новой вкладке с провенанс-баннером
   «📖 Из книги: … ↗». Может редактировать, экспериментировать.
2. В конце главы — блок «⚔ Практика», в нём линки на задачи в BSLexicon.
   Клик → страница задачи с условием и стартовым кодом.
3. Решает задачу → зелёные ✓ на чек-поинтах → в оглавлении раздела
   `/judge/` появляется отметка «пройдено». Прогресс в localStorage
   (позже — sync с GitHub через уже существующий Git-модуль).
4. На бумаге вместо клика — QR-код рядом с листингом или задачей.
